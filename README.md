# remplanner-mcp

MCP-сервер (stdio) для рисования планировок в [remplanner.ru](https://remplanner.ru): создание и открытие
проектов, комнаты и стены точными размерами, проёмы, двери и окна, несущие колонны, потолочные ригели,
мебель, сантехника и лестницы из каталога, валидация модели, рендер плана картинкой, сохранение с бэкапом и сверкой. 42 инструмента;
все размеры в миллиметрах.

Документация: `docs/design.md` (архитектура и факты о сайте), `docs/tasks.md` (план),
`docs/remplanner-features.md` (функции сайта), `CONTRIBUTING.md` (процесс разработки), `AGENTS.md`
(правила для агентов).

## Требования

- Node.js **≥ 22.18** (код на TypeScript исполняется напрямую, без сборки).
- **Chrome** (сервер запускает headless-браузер через `playwright-core`).
- Доступ к `remplanner.ru`.

Если корпоративная сеть подменяет TLS-сертификаты, добавьте свой корневой сертификат — **это опция,
обычно не нужна**:

```sh
export NODE_EXTRA_CA_CERTS=/путь/к/corp-root.pem   # при необходимости
```

## Установка

```sh
git clone https://github.com/pom6ac/remplanner-mcp.git
cd remplanner-mcp
npm install
npm run typecheck && npm test
```

## Учётные данные и вход

Учётные данные лежат в `~/.remplanner-mcp/credentials.env` (каталог 0700, файл 0600, создаётся вручную):

```
REMPLANNER_LOGIN=...
REMPLANNER_PASSWORD=...
```

Вход и проверка:

```sh
npm run login   # вход, сессия -> ~/.remplanner-mcp/state.json (0600)
npm run check   # статус: logged_in, тариф, число проектов
```

Можно работать и без аккаунта: анонимный проект создаётся инструментом `project_create` и живёт
в cookie-сессии сервера (`~/.remplanner-mcp/state.anon.json`), квоту аккаунта не занимает.

### Права доступа к файлам (POSIX)

Файлы с приватным содержимым (учётные данные, сессия, снимки, кэш каталога, рендеры) создаются
с правами `0600`, каталоги состояния — с `0700`. Существующие каталоги текущего пользователя
с широкими правами (например, `~/.remplanner-mcp` `0755`, оставшийся от старой версии) сервер
чинит сам (`chmod 700`) при первом обращении. Не чинятся молча и требуют ручного исправления:

- файл `credentials.env` с правами шире `0600` — отказ с подсказкой `chmod 600 <файл>`;
- каталог учётных данных, принадлежащий другому пользователю, — отказ;
- каталог резервных копий (`backups`), являющийся символической ссылкой (в том числе
  вынос на другой диск), — отказ; переносить нужно весь каталог состояния через
  `REMPLANNER_HOME`, а не отдельные подкаталоги.

На Windows и файловых системах без достоверных POSIX-прав (exFAT, SMB, vfat) проверка прав
не выполняется: сервер работает и разово предупреждает, что защита правами недоступна.

## Подключение к агентам

Замените `<путь-к-репозиторию>` на путь, куда склонировали репозиторий.

### Claude Code

```sh
claude mcp add -s user remplanner -- node <путь-к-репозиторию>/src/cli.ts serve
```

### OpenCode (`~/.config/opencode/opencode.json`)

```json
{
  "mcp": {
    "remplanner": {
      "type": "local",
      "command": ["node", "<путь-к-репозиторию>/src/cli.ts", "serve"],
      "enabled": true
    }
  }
}
```

### Codex (`~/.codex/config.toml`)

```toml
[mcp_servers.remplanner]
command = "node"
args = ["<путь-к-репозиторию>/src/cli.ts", "serve"]
startup_timeout_sec = 60
tool_timeout_sec = 120
```

Проверка: в клиенте должен появиться список из 36 инструментов `remplanner` (от `auth_status`
до `render_plan`). Полезные переменные окружения: `REMPLANNER_HEADED=1` (видимый браузер),
`REMPLANNER_ANON=1` (работать только анонимно), `REMPLANNER_BROWSER=<путь>` (свой Chrome).

## Ограничения MVP

- **Одна сессия на аккаунт.** Вход из MCP выбивает открытую вкладку сайта и наоборот. Пока агент
  работает, не открывайте ЛК и редактор remplanner.ru в браузере.
- **Бесплатный тариф — один проект** в аккаунте; второй создать нельзя (`PLAN_LIMIT`), копирование
  и этажи — PRO. Анонимные проекты квоту не занимают.
- **X-пересечения стен не поддержаны** (`UNSUPPORTED_JUNCTION`): стену в точке примыкания нужно
  разрезать `wall_split`.
- **Свободные концы стен допустимы** (как в редакторе): операция проходит с предупреждением
  `wall_free_ends` (список концов в мм); помещение образует только замкнутый контур стен.
- **Бэкап перед сохранением:** перед каждой записью снимок модели пишется в `~/.remplanner-mcp/backups/`,
  после сохранения модель на сервере сверяется повторным чтением. История изменений — в [CHANGELOG.md](CHANGELOG.md).

## Как пользоваться

Пример запроса агенту (в Claude Code / OpenCode / Codex с подключённым сервером):

> «Открой анонимный проект и нарисуй комнату 4000×3000 мм, сделай дверь на южной стене по центру
> и окно на северной, поставь диван вдоль западной стены. Покажи план и сохрани».

Типовой сценарий инструментов:

```
project_create            # анонимный проект (или project_open для проекта аккаунта)
room_add_rect             # комната 4000×3000
opening_add               # 20 типов дверей и все 7 типов окон (включая балконный блок);
                          #  замена проёма — replaces (план «Перегородки», план «до/после»)
wall_add kind=partition   # перегородки листа «Перегородки» (pgb|foam_block|brick|gypsum, PRO: glass, bar)
demolish / demolish_cancel  # пометки демонтажа стены, участка или проёма (лист «Демонтаж»)
pillar_add kind=gypsum_box  # ГКЛ-короб листа «Перегородки» (700×200 мм)
pillar_add                # несущая колонна (20×20 см по умолчанию)
rigel_add                 # потолочный ригель (ось start→end, толщина/высота 300 мм по умолчанию)
catalog_search + item_add # мебель, сантехника, лестницы (21 вид) и коммуникации (стояки, короб) из каталога
gas_line_add              # газовая линия (пункт меню «Коммуникации», отдельная сущность pipes_gas)
pipe_add                  # трубы водоснабжения/канализации (лист «Водоснабжение», kind: water|hot|drainage,
                          #  подключения к выводам воды waterspot_*, стоякам и коллектору)
led_strip_add / stripe_add / line_light_add  # освещение: лента, трековые шины (recessed|surface|pendent),
                          #  линейный свет (лист «Освещение», ломаные; светильники — item_add)
item_add socket/light_switch + cable_add      # электрика: розетки и выключатели (листы «Розетки»/«Выключатели»,
                          #  предмет-группа socket_group) и связь «выключатель → светильник» (cables)
warm_floor_add            # тёплый пол (лист «Тёплые полы»): контур kind: cable|infrared|water (водяной — PRO)
item_add conditioner/socket_thermo/fan/radiator_bimetal  # климат: кондиционеры (у стены), терморегулятор,
                          #  вентиляторы, радиаторы (листы «Кондиционеры»/«Вентиляция»/«Радиаторы»)
pipe_add kind=warm_floor|conditioner_drainage|heat_hot|heat_cold|vent_out|vent_in  # трубы климата (PRO)
finish_floor_set / finish_wall_set / finish_ceiling_set  # отделка: покрытия пола, стен (по сторонам
                          #  комнат) и потолка (листы «Напольные покрытия»/«Отделка стен»/«Потолки»)
floor_hole_add            # проем в полу (прямоугольник в комнате, level_holes)
terrace_add               # терраса (замкнутое кольцо границ terrace_borders) + terrace_fence_add / terrace_column_add
territory_add             # участок (замкнутое кольцо границ territory_borders)
balcony_add               # балкон (зелёные ограждения role «balcony», U-примыкание к наружной стене)
dim_add / dims_list       # ручные размеры (нижняя панель «Добавить размер»): отрезок в мм,
                          #  привязка концов к предметам (attach1/attach2), отступ, цвет
comment_add / comments_list  # текстовые комментарии с указателем (кнопка в UI — PRO):
                          #  текст до 600 символов, шрифт 8..30, привязка к предмету, url
model_validate            # проверка геометрии перед сохранением
render_plan               # PNG плана
project_save              # сохранение с бэкапом и сверкой
                          # (в ответе will_delete — число удаляемых объектов сервера
                          # по каждой коллекции model_get: walls, openings, items,
                          # pillars, rigels, gas_lines, pipes, …; warnings — где)
```

Типовые ошибки и их расшифровка — в таблице ниже.

| Код | Что означает | Что делать |
|---|---|---|
| `AUTH_REQUIRED` | нет `credentials.env` или `state.json` | выполните `npm run login` |
| `SESSION_TAKEN_OVER` | сессию выбил вход в другом месте | закройте вкладку сайта или подождите 10 минут, затем `npm run check` |
| `SAVE_CONFLICT` | `save_id` на сервере новее рабочей копии | `project_open` (перечитать) или `project_save` с `force: true` только по явному решению |
| `GEOMETRY_CONFLICT` | пересечение стен, проём вне стены | проверьте `model_validate`, разделите стену `wall_split` |
| `UNSUPPORTED_JUNCTION` | T/X-примыкание стен | разрежьте стену `wall_split` в точке примыкания |
| `OUTSIDE_ROOM` | предмет/точка вне помещений | задайте позицию внутри комнаты (метки `R1…` из `model_get`) |
| `NORMALIZATION_DROPPED` | редактор удалил элементы модели | проверьте `model_validate`: короткие стены, проёмы без опоры |
| `EDITOR_INCOMPATIBLE` | сайт обновился, контракт адаптера не прошёл | прогоните `npm run test:contract`, сверьте `src/editor/inject.js` |
| `EDITOR_PROJECT_MISMATCH` | редактор открыл другой проект | сохранение в чужой проект запрещено; перечитайте `project_open` |
| `CAPTCHA_REQUIRED` | сайт требует капчу | ручной `npm run login --headed` |
| `RATE_LIMITED` / `TIMEOUT` | лимит частоты (30 запросов/мин, сохранение ≤ 1 в 5 с) | повторите позже — лимитер встроен |

## Дорожная карта

Фаза 2 (`docs/phase2-design.md`) — поддержка правок существующей геометрии и richer-редактирование:
демонтаж и перенос стен с пересчётом примыканий, перегородки, электрика и вода (розетки, выводы),
отделка поверхностей; покрытие редактора сверяется с эталонными пробами, задачи F2-01…F2-12
в `docs/phase2-tasks.md`.
