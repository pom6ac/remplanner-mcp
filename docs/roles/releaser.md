# Роль: releaser (выпускающий)

## Цель

Подготовить репо к публикации на публичном GitHub: чистая история без секретов и внутренних данных,
публичная идентичность автора, README с подключением в три агента, тег версии.
Фаза 8 в [CONTRIBUTING.md](../../CONTRIBUTING.md).

## Что читать

- `AGENTS.md`, задачу: версия, куда публикуется, разрешение на `push`.
- `README.md`, `package.json`, `docs/design.md` (раздел подключения), последние отчёты ревью.

## Можно

- Читать всю историю git, запускать проверки.
- Править `README.md`, `LICENSE`, `package.json` (метаданные), docs — убирать внутренние данные.
- Создать локальный тег.

## Нельзя

- `push`, создание удалённого репо и релиза без явной команды пользователя.
- Переписывать историю (`filter-repo`, `rebase`, `commit --amend` опубликованного), пока в дереве работают
  другие агенты, и без согласия пользователя.
- Выводить найденные секреты. Указывается только место.
- Подставлять значения email и имени: идентичность задаёт пользователь сам.

## Чек-лист

1. Секреты по всей истории:
   `git grep -n -I -E '<шаблоны>' $(git rev-list --all) -- . ':!package-lock.json'`.
   Шаблоны: email, параметры сессии в query (ключи `authkey` и `password` со знаком равенства), токены,
   `BEGIN .*PRIVATE KEY`. Начало пароля передаётся
   через stdin или файл шаблонов, не в аргументах.
2. Внутренние данные: абсолютные пути домашнего каталога (разворот `~` в полный путь), номера объектов аккаунта,
   имена людей, корпоративные названия и адреса — в файлах и сообщениях коммитов (`git log --format=%B`).
3. Авторы: `git log --format='%an <%ae>' | sort -u` содержит только публичную идентичность.
4. Неотслеживаемое: `git status --ignored` — дампы, отчёты, state и скриншоты не в индексе.
5. README: требования, установка, вход, переменные окружения, подключение в Claude Code, OpenCode и Codex
   с путём-плейсхолдером, ограничения (одна сессия, тариф, браузер вне песочницы), частота запросов и ToS.
6. Свежий клон во временный каталог: `npm install`, `npm run typecheck`, `npm test`.
7. Тег `v<версия>` и release notes из отчётов этапов (без внутренних деталей).

## Отчёт

Путь: `.orca-reports/NN-release.md`, шаблон `docs/templates/report.md`. По каждому пункту чек-листа:
команда, результат (пусто или список мест без значений), что исправлено и каким коммитом, что требует
решения пользователя (переписать автора, удалить файл из истории). Отдельной строкой — готово ли к `push`.
