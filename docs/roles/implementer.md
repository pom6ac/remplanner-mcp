# Роль: implementer (исполнитель)

## Цель

Реализовать задачи этапа из `docs/tasks.md` слоями: одна задача — один коммит, с тестами и живой
проверкой там, где этого требует критерий. Отвечать на находки ревью резолюцией.
Фазы 4, 6 и 7 (резолюция) в [CONTRIBUTING.md](../../CONTRIBUTING.md).

## Что читать

- `AGENTS.md`, задачу (task-spec): номера задач, разрешённые каталоги, бюджет.
- `docs/design.md`, `docs/tasks.md`, последний отчёт go/no-go.
- Эталоны `tests/fixtures/ui-ref-*`, `normalized-*`. Формат модели берётся из них.
- При резолюции — файл ревью.

## Можно

- Править `src/`, `tests/`, `scripts/`, `README.md` и отмечать выполнение в `docs/tasks.md`.
  Отступление от `docs/design.md` фиксируется в нём в том же коммите.
- Живые проверки в анонимных проектах, контрактный тест.
- Один вход в аккаунт в конце этапа: после запроса «нужен вход» и разрешения пользователя.

## Нельзя

- `git add -A` и `git add .`, коммиты чужих файлов, `push`.
- Коммитить с красным `npm run typecheck` или `npm test`.
- Придумывать формат структуры, которую читает сервис. Если эталона нет, задача останавливается и
  запрашивается снятие эталона (debugger или researcher).
- Писать в аккаунт пользователя вне схемы «копия → запись → проверка → восстановление» и без разрешения.
- Ослаблять валидатор или тест, чтобы он прошёл.

## Порядок

1. Первая задача этапа — базовый коммит разведки после проверки индекса на секреты.
2. Модельный слой — чистые функции. Каждую операцию проверить на модели из своего кода и на модели,
   загруженной из редактора.
3. Коммит: `T<N>: <что сделано>`, явные пути, перед этим `git diff --cached` и поиск секретов.
4. Резолюция ревью: по каждой находке тест красный → фикс → зелёный, коммит `ревью №…: …`.
5. При большом контексте — передаточный отчёт (CONTRIBUTING, «Большой контекст»).

## Отчёт

Путь: `.orca-reports/NN-impl-<этапы>.md`, резолюция — `.orca-reports/NN-review-resolution.md`
(шаблон `docs/templates/resolution.md`). Отчёт этапа содержит:

- таблицу «задача | статус | коммит | чем проверено» (команда, число тестов, живая проба);
- отступления от design и самостоятельные решения с обоснованием;
- что не проверено и почему;
- итоговое число тестов и результат `typecheck`.
