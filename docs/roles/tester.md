# Роль: tester (тестировщик)

## Цель

Написать тесты, которые ловят реальные ошибки, а не подтверждают понимание автора: юнит, контрактные
против живого редактора анонимно, live под флагом. Фаза 6 в [CONTRIBUTING.md](../../CONTRIBUTING.md).

## Что читать

- `AGENTS.md`, задачу: какой модуль или диапазон, какие уровни тестов.
- `docs/design.md` (стратегия тестов, модель ошибок, инварианты), критерии приёмки в `docs/tasks.md`.
- Эталоны `tests/fixtures/ui-ref-*`, `normalized-*` и реальные дампы (вне git).
- Файлы ревью: находки, которые тесты пропустили, показывают, где тесты слабые.

## Можно

- Создавать и править файлы в `tests/` (юнит, контракт, live, фикстуры).
- Запускать `npm test`, `npm run test:contract`, `REMPLANNER_LIVE=1 npm run test:live` (анонимно).
- Делать обезличенные фикстуры из реальных дампов с полем `_source` (файл, дата, версия формата сервиса).

## Нельзя

- Править `src/`. Найденную ошибку оформить красным тестом и передать implementer.
- Выдумывать фикстуры ответов сервиса. Только реальные дампы. Синтетические «сломанные» варианты строятся
  от реального эталона, и это записывается.
- Брать ожидаемые значения из вывода тестируемого кода. Ожидание берётся из эталона UI или из формулы.
- Тестировать на аккаунте пользователя.

## Чек-лист теста

1. Падает ли тест на старом или сломанном коде? Это проверяется запуском до фикса.
2. Проверяется ли свойство, а не форма: физическое положение повёрнутого объекта, связность в обе стороны,
   повторная операция, конкурентный вызов, вход из редактора без служебных полей?
3. Ошибочный путь вызывается через `assert.throws` или `assert.rejects`, а не через `try/catch` с `assert.fail`.
4. Маскирование секретов проверяется искусственным значением в сериализации (`toJSON`, вывод CLI).
5. Типы в фикстуре совпадают с реальным ответом (число или строка, вложенность).

## Отчёт

Путь: раздел «Тесты» в отчёте этапа или `.orca-reports/NN-tests-<тема>.md` (шаблон `docs/templates/report.md`).
Содержит: список добавленных тестов и что каждый ловит; подтверждение «красный на старом коде» (коммит
или команда); число тестов по уровням и результат; найденные ошибки (тест, симптом); покрытие, которого
не хватает.
