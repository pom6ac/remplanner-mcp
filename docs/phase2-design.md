# remplanner-mcp — проект фазы 2

Статус: черновик 16.11.2026 по итогам разведки этапа 15 (`.orca-reports/15-phase2-research.md`). Факты и пометки
**[код]** / **[проверить]** — в [coverage.md](coverage.md). Основной проект — [design.md](design.md); фаза 2 его не
меняет, а дополняет. Задачи — [phase2-tasks.md](phase2-tasks.md).

## 1. Цель и границы

Агент через MCP рисует на листах, кроме исходного плана и мебели:
1. **Перепланировка** — демонтаж (лист `break_walls`, `b`) и перегородки (`create_walls`, `c`): новые стены, ГКЛ-короба,
   зонирование, проёмы на перегородках и замена дверей.
2. **Сантехника и вода** — стояки и ввод на исходном плане, выводы воды и канализации, трубы.
3. **Электрика и свет** — розетки и выводы проводов, выключатели, светильники, щиток как предмет, связи выключателей
   со светильниками, кабели.
4. **Отделка и размеры** — названия помещений, полы (покрытие, подъём), потолки (тип, опуск), отделка стен (участки,
   высоты), размерные линии, комментарии.

Вне границ фазы 2:
- конструктор щитка (`shields`) и «Построить автоматически» — PRO старших тарифов, сложная модель;
- развёртки как редактируемый объект (молдинги, ниши, профили), 3D, PDF, DXF;
- фигуры, линии, изображения (PRO), гидроизоляция, штукатурка, стяжка, тёплые полы, вентиляция, кондиционеры;
- зоны пола и потолка, плинтусы, закарнизные ниши, точка укладки (PRO; можно добавить при PRO-аккаунте);
- **любая PRO-сущность на бесплатном тарифе** (§4).

## 2. Принципы

Фаза 2 продолжает вариант G из design §12: **Node задаёт намерение и геометрию, производные считает редактор**.

1. **Перегородки и демонтаж — это стены других листов.** Перегородка — стена `plan:"c"`, демонтаж — поля стен
   `plan:"a"` (`demount`, `sectors`, `holes[].demount`). Правила §12.3 (узлы точно в точку, T-конец на грань несущей,
   вычитание общих интервалов, атомарность на клоне) действуют для `plan:"c"` так же, но несущими для перегородки
   считаются стены обоих листов, кроме демонтированных. Связи и комнаты листа `c` строит редактор при `draw`
   (`preparePlan("c")`: `split_by_holes`, `get_free_zones`) [код].
2. **Точки на стене — это предметы.** Розетки, выключатели, выводы, бра, щитки, коробки, выводы воды хранятся в `items`.
   Node ставит центр предмета на внутреннюю грань стены и поворачивает его вдоль грани. Поля `id_wall`, `wall_direction`,
   `wall_line`, `id_room` пишет редактор (`Item.findWall`, `setParents`) [код]. Группы (`socket_group`) Node собирает
   по эталону F2-01 [проверить].
3. **Отделка живёт в `rooms2` и создаётся редактором.** Node не создаёт `rooms2` и элементы `floors[]`, `ceilings[]`,
   `decors`, а только меняет поля уже существующих элементов нормализованной модели: `cover`, `f0offset`, `type`,
   `level`, `profile`, `name`, `color`. Так же делает и сам инструмент UI (§2 coverage). Если элемента нет (комната
   только что появилась), сначала нормализация, потом правка. Участки отделки стен (`decors.parts`) — по эталону
   F2-01: формат линий (`line`, `line_wall`) Node строит из грани стены [проверить F2-02].
4. **Линии-графы (трубы, кабели, связи выключателей, шины) строит Node по эталону** — `vertexes` (id предметов и узлов),
   `matrix`, `items`, плюс обратные ссылки в `props` предметов. Если круг restore → draw → save их теряет (F2-02),
   запасной путь — методы редактора в `page.evaluate` (`GraphLines.addItem`/`addNew` через `$ManagerLining`) [проверить].
5. **Изменение стен после отделки.** При перестройке комнат редактор переносит отделку эвристикой `$Restorer`, она может
   сброситься. Мутация стен, после которой у комнаты пропали `floors[].exist`, `ceilings[].exist` или `decors`,
   возвращает предупреждение `FINISH_RESET` со списком комнат (не ошибку: это поведение самого сайта, урок 5).
6. **Единицы** — как в MVP: мм на входе и выходе, X вправо, Y вниз, углы по часовой стрелке. Высоты: розетки,
   выключатели, выводы — до центра; светильники и мебель — до нижнего края (FAQ 7.24).

## 3. Инструменты

Общие правила design §7 действуют: мутация меняет рабочую копию, `project_save` сохраняет, ответ — diff и предупреждения.
Новые идентификаторы — родные id сайта. Каждый инструмент проверяет тариф (§4) **до** изменения модели.

### 3.1 Перепланировка

| Инструмент | Параметры (мм) | Что делает | Ошибки |
|---|---|---|---|
| `demolish` | `target: wall\|opening\|item`, `id`; для стены — `range?: {from: start\|end, offset_mm, length_mm}` | без `range` — `demount=1` (вся стена); с `range` — участок `sectors[sid]={pc, width}` на оси; проём — `holes[hid].demount=1`; предмет исходного плана (радиатор, щиток) — `props.demount=1` | `NOT_FOUND`; `INVALID_ARGUMENT` (стена `plan:c`, балкон — UI тоже запрещает; проём уже заменён); участок за пределами стены |
| `demolish_cancel` | `target`, `id`, `sector_id?` | обнуляет те же поля | `NOT_FOUND` |
| `wall_add` / `walls_add_polyline` / `room_add_*` (расширение) | `kind: partition` + `material: pgb\|foam_block\|brick\|gypsum\|glass\|bar` | материал → код `c_*` по эталону F2-01; `glass`, `bar` — PRO | `NOT_AVAILABLE_ON_TARIFF` |
| `opening_add` (расширение) | `replaces?: opening_id` | новый проём `plan:"c"` поверх исходного (замена двери) | проём-источник демонтирован |
| `pillar_add` | `kind: column\|gypsum_box`, `center{x,y}`, `width_mm`, `depth_mm`, `angle_deg=0`, `height_mm?` (только короб) | колонна `plan:"a"` или ГКЛ-короб `plan:"c"`, `role_:"gypsum"` (design §7.2 предусматривал `pillar_add`; фаза 2 добавляет `kind`) | `GEOMETRY_CONFLICT` (пересечение со стеной) |
| `zone_line_add` | `kind: room`, `points[]` (≥ 2, концы на гранях стен) | линия зонирования `zone_delimiters` `type:"zone_c"`; помещение делится на зоны со своей площадью | `GEOMETRY_CONFLICT`, если концы не на стенах; `kind: floor\|ceiling` — PRO |

Правила: демонтированная стена и её участок не участвуют в листе `c` как несущие; новый проём на стене `plan:"a"` в листе `c`
допускается только как замена (`replaces`). Демонтаж по смыслу — инструкция для строителей, а не удаление; удаление стены —
по-прежнему `wall_delete`.

### 3.2 Точки на стене и в помещении (сантехника, вода, электрика, свет)

| Инструмент | Параметры (мм) | Что делает |
|---|---|---|
| `fixture_add` | `name` (ключ каталога: `socket`, `light_switch`, `wire_light`, `waterspot_cold_hot`, `bra`, `electric_shield`, `drainage_column`, …); **на стене**: `wall_id`, `offset_mm` + `from: start\|end` (до **центра** точки вдоль внутренней грани), `side?: auto\|left\|right` (по умолчанию — сторона помещения), `height_mm?` (до центра; по умолчанию из каталога `over_floor`), `drainage_height_mm?` (узлы с канализацией); **или** `group_with: item_id`, `position: below\|above\|next` (вторая точка в рамке, второй и третий контур); **в помещении** (потолочные, напольные): `center{x,y}` или `room_center: room_id` (люстра «по центру», ½) | создаёт предмет на нужном листе (лист из `catalog.plan`); центр — на грани стены, угол — вдоль грани; редактор после нормализации пишет `id_wall`. Ответ: `item_id`, лист, стена, сторона, расстояние до ближайшего угла (как подсветка UI) |
| `item_update` / `item_delete` (MVP) | `height_mm`, `offset_mm` вдоль той же стены, `vertical_group?: bool` | перемещение по стене, высота, удаление |
| `network_add` | `kind`: `water_cold\|water_hot\|drainage` (трубы), `cable:<ключ кабеля>` (`wire_3_25`, …), `switch_link` (выключатель → светильник), `led\|track\|line_light`; `path[]`: элементы `{item_id}` или `{x,y}` (узел); для `switch_link`: `switch_id`, `key?: 1..3`, `light_ids[]` | строит граф `vertexes/matrix/items` + обратные ссылки у предметов; для кабелей и связей проверяет, что концы — подходящие предметы (щиток, коробка, розетка, выключатель, светильник). **Все виды — PRO** на текущей разметке (`water_pipe`, `wire_*`, `cable`, `led_strip`, `*_strip`) |

Почему один `fixture_add`, а не `socket_add`/`switch_add`/`waterspot_add`: механика у всех точек одна (предмет, якорь
`wall`, высота до центра, группировка рамкой), различаются только ключ каталога и лист. Каталог (`catalog_search`, фильтр
`sheet`) подсказывает ключ. `item_add` (MVP) остаётся для мебели, сантехники и предметов без привязки к стене.

Правила привязки (Node проверяет до нормализации, редактор подтверждает после):
- точка на стене: центр на внутренней грани (ось ± depth/2 в сторону помещения) в пределах грани с отступом ≥ половины
  ширины точки от углов; не поверх проёма (кроме выводов над столешницей и т. п. — разрешено, если `height_mm` выше
  или ниже проёма); иначе `GEOMETRY_CONFLICT{kind:"on_opening"}`;
- стояк и ввод — `items_on_walls`: у стены или в углу, внутри помещения, на исходном плане;
- потолочные и напольные точки, люстры — внутри помещения (`OUTSIDE_ROOM`), `room_center` даёт центр прямоугольной комнаты;
- группа: не больше 3 контуров по высоте (третий контур — анонс 03.12.2024), в группе розетки, выключатели,
  терморегуляторы [проверить формат `socket_group` в F2-01];
- щиток — предмет `electric_shield*` на стене, `height_mm` по умолчанию 1200; содержимое щитка не редактируется;
- кабель (PRO) начинается у щитка или распределительной коробки; связь выключателя (PRO) — от свободной клавиши.

### 3.4 Чтение и проверка (расширения)

- `model_get` `include` получает разделы `demolition` (стены и участки, проёмы, предметы), `partitions`, `fixtures`
  (по листам: стена, сторона, расстояние до угла, высота), `networks` (вид, вершины, длина редактора), `finishes`
  (по комнатам: пол, подъём, потолок, опуск, участки стен), `annotations` (размеры, комментарии).
- `model_validate` — новые проблемы: точка не на грани стены после нормализации (`id_wall` пуст), точка поверх проёма,
  PRO-сущность в модели на бесплатном тарифе (сущность могла остаться от старого PRO или прийти из `.plan` — сообщаем,
  не удаляем), сброшенная отделка (`FINISH_RESET`), граф с висячей вершиной.
- `render_plan` — `sheet` из списка листов: `break_walls`, `create_walls`, `rooms`, `santeh`, `waterplan`, `sockets`,
  `light_connections`, `light`, `cables`, `floor`, `walls`, `ceiling` (переключение уже есть в адаптере, design §7.6).

## 4. Тариф

- Источник истины — разметка редактора текущей сессии: `#plannertool_<ключ>.is_pro`, классы `is_pro` у групп и кнопок
  нижней панели (комментарий, «нарисовать элемент», изображение). Адаптер читает список при открытии редактора и кеширует
  его по `global_version` (так же, как каталог). Для аккаунта PRO список пуст или класс отсутствует [проверить на PRO].
- `auth_status.tariff` (`free\|pro\|unknown`) и этот список дают `NOT_AVAILABLE_ON_TARIFF{tool, key}` до мутации.
  Неизвестный тариф трактуется как бесплатный.
- Анонимный режим равен бесплатному тарифу: живые тесты PRO-инструментов (трубы, кабели, связи выключателей, комментарии)
  невозможны без PRO-аккаунта. Такие инструменты реализуются только после подтверждения пользователя, что аккаунт PRO,
  и проверяются в аккаунте по схеме «копия → запись → проверка → восстановление» (AGENTS.md, правило 3).

## 5. Как агент проверяет результат

1. Ответ мутации: diff (созданные id, лист, стена, сторона, расстояние до угла, высота) и предупреждения нормализации
   (`FINISH_RESET`, `EDITOR_REQUIRED_FOR_ROOMS`).
2. `model_get include=[…]` — числа: расстояние розетки до угла и высота, подъём пола, опуск потолка, площади зон после
   зонирования, длина демонтированного участка.
3. `model_validate` — инварианты §3.4.
4. `render_plan` **нужного листа**: демонтаж — `break_walls` (красная штриховка), перегородки — `create_walls`, розетки —
   `sockets` (отметки высот), выключатели и связи — `light_connections` (зелёный — соединено), свет — `light`, вода —
   `waterplan`, полы — `floor`, потолки — `ceiling`, стены — `walls`, имена — `rooms`.
5. После `project_save` — `project_open fresh:true` и сверка разделов (`roundtrip_ok`).

Рекомендованный сценарий в описаниях инструментов: «нормализованная планировка → демонтаж и перегородки →
`render_plan create_walls` → точки и свет → `render_plan sockets` → отделка → `render_plan floor` → `project_save`».
Отделку ставить после окончательной планировки (иначе `FINISH_RESET`).

## 7. Риски

| Риск | Мера |
|---|---|
| Формат групп розеток, графов и участков отделки не выводится из кода однозначно | эталоны F2-01 до реализации; круг restore → save → reload в F2-02; запасной путь — методы редактора |
| Отделка сбрасывается при изменении стен | предупреждение `FINISH_RESET`; рекомендация «отделка — последней» в описаниях инструментов |
| Ключи материалов `c_*` и типов укладки не задокументированы | эталон F2-01; zod-перечисления строятся из эталона, а не из догадки |
| PRO-сущности в модели (из `.plan` или после окончания PRO) | `model_validate` сообщает, MCP их не создаёт и не удаляет |
| PRO-инструменты нельзя проверить анонимно | реализация только при PRO-аккаунте, проверка по правилу 3 |
| Редактор меняет поведение (`global_version`) | контрактный тест фазы 2 (F2-11) по эталонам; `EDITOR_INCOMPATIBLE` |
| Расчёты (метраж, сметы) зависят от высот точек | высоты по умолчанию из каталога; в ответе `fixture_add` высота всегда явная |
