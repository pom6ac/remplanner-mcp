# CHANGELOG

## 0.1.1 — 2026-11-16

Исправлены три дефекта MVP из первого пользовательского испытания
(отчёт user trial 1) и находки независимого ревью v0.1.1 (отчёт 18).

### Исправлено (ревью v0.1.1)

- **Касание стены вплотную ошибочно считалось выходом за комнату** (№1). Отрицательный
  допуск в проверке углов bbox исключал проверку попадания угла на границу: предмет,
  касающийся внутренней грани без пересечения, получал `ITEM_OUTSIDE_ROOM` с вылетом
  0 мм. Теперь геометрический допуск 1 мм в пользу «внутри»; реальное проникновение за
  допуск остаётся ошибкой с вылетом в мм.
- **Валидную пустую модель нельзя было открыть** (№2). Новый или очищенный проект
  приравнивался к потере данных (`MODEL_PARSE_EMPTY` при непустом `data` или
  `save_id > 0`; `save_id` не доказывает наличие объектов). Теперь `MODEL_PARSE_EMPTY` —
  только когда `data` непустой, разбор дал пустую модель, а в сыром JSON есть
  необработанные сущности; пустой проект открывается и сохраняется (защита от
  затирания непустого сервера сохранена).
- **PNG без предметов мог отдаваться при ошибке ожидания отрисовки** (№3). Ошибка
  ожидания предметов в SVG подавлялась, после чего возвращался PNG без предметов.
  Теперь видимость предметов проверяется по реальным DOM-элементам на листе (не
  подстрокой в `innerHTML`); при таймауте — `RENDER_OUT_OF_SYNC` без скриншота.
  Ожидаются только предметы запрошенного листа (слои остальных на листе скрыты).
- **Слияние коллинеарных стен отвергалось как потеря** (№4). Точное равенство числа
  стен в save и render_plan (и в адаптере) отвергало допустимую нормализацию —
  редактор сливает коллинеарные стены (design §12). Стены сравниваются по покрытию
  осей (объединение отрезков по прямым, допуск 1 мм + 0.1%), проёмы и предметы —
  по id; реальная потеря объекта по-прежнему ошибка.
- **`will_delete` считал разность общих счётчиков, а не удаления** (№5). Удаление
  существующего предмета/проёма с добавлением нового маскировало удаление. Теперь
  перечисляются id объектов сервера, которых нет в рабочей копии (до 10 id в каждом
  предупреждении).
- **Тест переключения листа проверял мёртвую функцию** (№6, minor). `pickSheetStrategy`
  не вызывался production-кодом; тесты идут через единственную реализацию
  `switchSheetInPage`, дубликат удалён.
- **Тесты пишут снимки во временный каталог** (инфра). `save`-тесты писали бэкапы в
  `~/.remplanner-mcp/backups` (10 падений EPERM в песочнице ревьюера); каталог
  состояния переопределяется переменной `REMPLANNER_HOME`.

### Исправлено (испытание)

- **`render_plan` рисует не текущую модель** (критично). Перед скриншотом в редактор
  синхронизируется вся каноническая модель workspace — стены, проёмы и предметы
  (тем же restore→draw→copy, что перед сохранением). Если счётчики объектов у
  редактора расходятся с моделью — ошибка `RENDER_OUT_OF_SYNC`, картинка не отдаётся.
  Ответ содержит ревизию: `model_hash`, `save_id` и счётчики стен/проёмов/предметов
  в модели и у редактора. Переключение листа теперь идёт кликом по навигации, как в
  UI (`$Project.setPlanName` не включает слои листа — предметы оставались невидимыми),
  и `render_plan` ждёт отрисовки предметов в SVG перед скриншотом. Мебель отрисовывается
  на листе `furniture` (на листе `init` её слой выключен самим сайтом).
- **`model_validate` проверял только центр предмета.** Теперь проверяется прямоугольник
  предмета с учётом поворота: выход за внутренние грани комнат — `ITEM_OUTSIDE_ROOM`
  с величиной вылета в мм; пересечение с телом стены — новый код `ITEM_INTERSECTS_WALL`
  с вылетом в мм. Касание внутренней грани (`against_wall` с `gap_mm=0`, допуск 1 мм)
  и нахождение в проёме проблемой не считаются; если центр предмета вне комнат —
  `ITEM_OUTSIDE_ROOM` отмечается и для предмета в проёме.
- **`project_open` мог молча вернуть пустую модель.** Если сервер вернул непустой `data`
  или у проекта `save_id > 0`, а разобранная модель пустая — ошибка `MODEL_PARSE_EMPTY`.
  Сохранение проекта, открытого с пустой моделью при непустой серверной версии,
  блокируется (`SAVE_CONFLICT`) без явного `force: true`. Кроме того, `project_save`
  сверяет число стен, проёмов и предметов с серверной версией и возвращает `will_delete`
  и `warnings` — сколько объектов сервера будет удалено.
