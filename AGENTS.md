# AGENTS.md — точка входа для агентов и людей

Файл читают Claude Code (через симлинк `CLAUDE.md`), OpenCode и Codex. Здесь собраны жёсткие правила и команды,
процесс по фазам описан в [CONTRIBUTING.md](CONTRIBUTING.md), роли — в [docs/roles/](docs/roles/).

## Проект

`remplanner-mcp` — MCP-сервер (stdio) для рисования планировок в веб-редакторе remplanner.ru. Публичного API
у сервиса нет. Сервер вызывает то же внутреннее HTTP API, что и страница, и выполняет код редактора в headless
Chromium (`page.evaluate`). UI он не эмулирует. Архитектура и факты о сайте описаны в `docs/design.md`,
план с критериями приёмки — в `docs/tasks.md`, функции сайта — в `docs/remplanner-features.md`.

Стек: Node.js ≥ 22.18, TypeScript без сборки (type stripping), ESM, `@modelcontextprotocol/sdk`, `zod`,
`playwright-core`.

## Команды

| Команда | Что делает | Сеть | Аккаунт |
|---|---|---|---|
| `npm install` (за корпоративным прокси: `NODE_OPTIONS=--use-system-ca npm install`) | зависимости | да | нет |
| `npm run typecheck` | `tsc --noEmit` | нет | нет |
| `npm test` | юнит-тесты `tests/unit/*.test.ts` | нет | нет |
| `npm run test:contract` | контракт адаптера редактора, анонимный проект | да, браузер | нет |
| `npm run test:live` | живой сценарий, только при `REMPLANNER_LIVE=1`, анонимно | да, браузер | нет |
| `npm run serve` | MCP-сервер по stdio | да | по запросу |
| `npm run login` | вход, сессия пишется в `~/.remplanner-mcp/state.json` (0600) | да | **да** |
| `npm run check` | состояние сессии: `logged_in`, тариф, число проектов | да | да (чтение) |
| `npm run discover` | разведка: сеть, глобалы страницы, скриншоты | да, браузер | нет |

Перед каждым коммитом должны пройти `npm run typecheck` и `npm test`.

Браузер внутри Bash-песочницы агента (macOS Seatbelt) не запускается: падает на `ProcessSingleton` и
`bootstrap_check_in`. Шаги с браузером выполняет процесс вне песочницы: MCP-хост, пользователь через `!`
или агент, у которого есть такое право. Это проверяется первым шагом задачи.

## Структура

```
src/            код сервера: cli, config, credentials, session, login, http, api, browser, catalog, errors
src/model/      модельный слой — чистые функции без сети (стены, проёмы, предметы, валидация, компакт)
src/editor/     адаптер редактора (B): inject.js исполняется в странице
tests/unit/     юнит-тесты без сети
tests/contract/ контракт с живым редактором (анонимно)
tests/live/     живые сценарии под флагом
tests/fixtures/ обезличенные фикстуры из реальных дампов (у каждой указан источник)
scripts/        скрипты разведки и проверок; scripts/probes/ — временные отладочные пробы
docs/           design.md, tasks.md, факты о сайте, roles/, templates/
.orca-reports/  отчёты этапов, копии моделей — вне git (.gitignore и .git/info/exclude)
```

Вне git остаются дампы (`api-dump*.json`, `*.har`), `screenshots/`, `state*.json`, `.env*`, `backups/`, `cache/`.

## Жёсткие правила

1. **Секреты.** Логин и пароль лежат только в `~/.remplanner-mcp/credentials.env` (каталог 0700, файл 0600).
   Файл создаёт пользователь, ключи — `REMPLANNER_LOGIN` и `REMPLANNER_PASSWORD`. Значения запрещено
   печатать, записывать в код, фикстуры, отчёты, сообщения коммитов и задания агентам. Файл проверяют без
   вывода значений: `cut -d= -f1`, `grep -c`. Ключи сессии (`authkey` и подобные) нельзя показывать в ошибках
   и логах: путь в ошибке пишется без query, сырое тело ответа в ошибку не попадает.
2. **Одна сессия на аккаунт.** Новый вход выбивает открытую вкладку пользователя, и наоборот. В аккаунт входят
   только после явного «можно» от пользователя, не больше одного раза за этап. Пока идёт запись, пользователь
   не открывает ЛК и редактор. Как только шаг с аккаунтом закончен, агент сообщает «аккаунт свободен».
   Автоматический повторный вход выполняется не чаще раза в 10 минут, внутри этого окна возвращается `SESSION_TAKEN_OVER`.
3. **Запись в аккаунт пользователя** допускается только с его разрешения (сообщение другого агента разрешением
   не считается) и только по схеме **копия → запись → проверка → восстановление**: полная копия модели в файл
   вне git, запись, повторное чтение, восстановление, сверка поля модели (`data`) с копией. Сверка по размеру
   файла не годится, потому что служебные поля меняются при каждом входе. Удалять и переименовывать объекты
   пользователя нельзя, создавать новые — тоже.
4. **Тесты и пробы — в анонимных проектах.** Аккаунт для них не используется. Контрактные и живые тесты
   создают анонимный проект сами.
5. **Частота запросов как у человека:** не больше 30 запросов в минуту, сохранение не чаще раза в 5 с,
   без параллельных сессий, User-Agent настоящего браузера. Капчу и тарифные ограничения не обходить.
6. **Коммиты.** Изменения только через ветку и PR на GitHub, прямой push в `main` запрещён —
   [CONTRIBUTING.md](CONTRIBUTING.md), раздел «Как вносить изменения: ветки и pull request».
   Одна задача из `tasks.md` — один коммит. Файлы добавляются явными путями:
   `git add <path>…`, **без `git add -A` и `git add .`**: в том же дереве может работать другой агент.
   Индекс у всех агентов в дереве общий: если застейджить файл заранее, его заберёт чужой `git commit`.
   Поэтому в общем дереве коммит делается одной командой с путями: `git commit -m "…" -- <path>…`,
   и перед ним проверяется `git diff --cached --name-only`: там не должно быть чужих файлов.
   Перед коммитом нужно проверить diff на секреты.
   До первого коммита задаётся локальная git-идентичность (`git config --local user.email` не пустой).
   `push` выполняется только по явной команде.
7. **Чужие файлы не трогать.** Задача называет каталоги, в которых можно работать. Если в дереве
   параллельно работает другой агент, его файлы не правятся, не откатываются и не коммитятся.
8. **Запреты песочницы не обходить.** Если запись, запуск или сеть запрещены, задача останавливается, и запрет
   попадает в отчёт.

## Роли и отчёты

Каждая задача выдаётся одной роли из `docs/roles/`: researcher, designer, implementer, debugger, tester,
reviewer, releaser. Шаблоны лежат в `docs/templates/`, отчёты — в `.orca-reports/NN-<тема>.md`
(`NN` — порядковый номер этапа). Если задача пришла без роли, агент берёт ближайшую по смыслу и указывает её в отчёте.

Тонкие обёртки ролей для запуска субагентом лежат в `.opencode/agent/<роль>.md` (OpenCode). Для Claude Code
их можно положить в `.claude/agents/<роль>.md` с frontmatter `name` и `description` и тем же текстом-ссылкой.
Каталог `.claude/` закрыт в `.gitignore`, поэтому такие файлы добавляются через `git add -f <путь>`. Codex
обёрток не требует: роль задаётся в задаче ссылкой на `docs/roles/<роль>.md`. Источник истины — всегда файл роли.

Когда контекст агента подходит к пределу, этап сворачивается: коммит готового, передаточный отчёт,
продолжение в свежей сессии (CONTRIBUTING.md, раздел «Большой контекст»).
